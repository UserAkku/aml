Part 1 — Traditional Programming

Sabse pehle: Programming hoti kya hai?

Bilkul basic level se shuru karte hain. Suppose tum computer ko bolna chahte ho:

"Agar student ka score 40 se zyada hai toh PASS, warna FAIL."

Computer khud se nahi jaanta:
❌ Score kya hai
❌ PASS ka matlab kya hai
❌ 40 kyun threshold hai
❌ Output PASS/FAIL kyun hona chahiye

Tumhe explicitly batana padta hai: 
if marks >= 40:
    result = "PASS"
else:
    result = "FAIL"
Yahan logic tumne banaya. Computer bas execute kar raha hai.

Abstract Picture — Traditional Programming

HUMAN │ │ writes rules manually ▼ ┌───────────────────┐ Data │ PROGRAM │ → Answer → │ (Rules + Logic) │ └───────────────────┘ Formula: DATA + RULES → ANSWERS
Traditional Programming: DATA + RULES → ANSWERS

"Rule" ka matlab kya hota hai?

Rule = computer ko diya gaya decision logic.

Age > 18 → Adult
Age ≤ 18 → Minor

Temperature > 38°C → Fever
Temperature ≤ 38°C → Normal

Spam Example — Yahin se ML ki Zarurat Samjho!

Tumne program banaya:

if "FREE" in email:
    spam = True
Spammer likhta hai: "Get your FR33 crypto reward!"

Tumhara rule "FREE" search karta tha. "FR33" mein FREE nahi → Program bolta hai: Not Spam! 😱

Tum patch karte ho:
if "FREE" or "FR33" in email:
Spammer phir likhta hai: "F-R-E-E crypto deal"

Phir se escape! Phir patch. Yeh loop kabhi khatam nahi hoga.

Spammer: "Congratulations!!! Claim your reward..."

No FREE, no FR33 — phir bhi spam hai! Par rule nahi pakad sakta.

Yeh "programmer ne enough if-else nahi likhe" wali problem nahi hai. Deep problem hai: Computer ko actual underlying pattern nahi pata!

Fundamental Problem

Traditional Programming

  • Human fixed rules likhta hai
  • World changes → rules outdated
  • Edge cases infinite hain
  • Computer knows only what you wrote

Real World

  • Unknown complexity
  • Infinite edge cases
  • Patterns change over time
  • Human can't write every rule

"Structurally Rigid" ka Matlab

Rule: if rain > 50mm: delay_delivery

But kya hoga agar:
→ Rain sirf 35mm hai but roads flooded hain?
→ Snow hai?
→ Traffic jam hai?
→ Bridge broken hai?
→ Strike hai?

Program ne ye rules explicitly nahi dekhe → Problem!

Best Analogy 🍳

🍳 Idiot-Proof Recipe

1. Take 2 eggs
2. Add 100g flour
3. Mix for 3 minutes
4. Bake at 180°C

Computer bolega: "Jo likha hai woh karunga."

Computer khud nahi sochega: "Hmm batter thoda dry hai, shayad aur milk chahiye."

→ Intelligence rule-writing side pe hai, execution machine karti hai.

Part 5 — Labelled vs Unlabelled Data

Ek Aur Important Axis

Question: Machine ke paas data hai, lekin kya correct answer bhi diya hua hai? Yeh decide karta hai learning setup!

✅ Labelled Data

Input + Ground Truth Answer

❌ Unlabelled Data

Sirf Input, koi answer nahi

image1    →    ?

Ground Truth Kya Hota Hai?

💡 Simple Definition

"Ground truth" = Correct/reference answer jo hum target maante hain.

Question: 2 + 2 = ?

ML Example:
Image → Cat
Ground truth = "Cat"

Part 6 — Char Learning Paradigms

1. Supervised Learning 👩‍🏫

Naam se intuition: "Teacher hai!" Teacher tumhe question ke saath correct answer bhi de raha hai.
House = 1200 sq ft → ₹70 lakh
House = 1800 sq ft → ₹1 crore
House = 900 sq ft → ₹50 lakh

Model ka goal: Input → Output → f(X) ≈ Y

New example: 1500 sq ft → Model predicts price!
DATA + CORRECT ANSWERS ↓ MODEL ↓ learn mapping (X → Y)

2. Unsupervised Learning 🧭

Ab teacher chala gaya 😭 No answers. Lekin algorithm khud similarities discover karta hai!
Customer A → purchase pattern
Customer B → purchase pattern
Customer C → purchase pattern
...

Nobody tells model: "Ye premium customer hai."

Algorithm discover kare:
● ● ● ● ● ● → Cluster 1 ▲ ▲ ▲ ▲ ▲ ▲ → Cluster 2 ■ ■ ■ ■ ■ → Cluster 3
Without being told category names beforehand!

3. Semi-Supervised Learning 🎭

Part-time teacher 😅 — Kuch labelled data + bahut saara unlabelled data
10,000 images total:
→ 100 labelled ✅
→ 9,900 unlabelled ❓

Labelling expensive hai, toh:
small labelled dataset + huge unlabelled dataset → model!

Google Photos example:
Photos → similar faces cluster → tum ek identity provide karo → system baaki related images associate kar leta hai!

4. Reinforcement Learning 🎮

⚠️ RL ko Supervised se mix mat karna!

RL mein koi teacher nahi deta ki "when wind = 30 km/h, rotor A ko 17° rotate karo."

┌──────────────┐ │ AGENT │ (Drone/Player/Robot) └──────┬───────┘ │ takes ACTION ▼ ┌──────────────┐ │ ENVIRONMENT │ (World) └──────┬───────┘ │ state + reward/penalty │ └──────────► AGENT learns!
Drone moves left → crashes → -10 reward 😢
Drone stabilizes → reaches destination → +100 reward 🎉

Over many interactions: agent tries to learn which actions lead to better cumulative rewards.
🔑 RL ≠ "No Data"

RL static pre-collected dataset pe dependent nahi hai. Agent environment se interact karke apna feedback generate karta hai!

Supervised: Dataset → learn
Unsupervised: Dataset → discover
RL: Interact → experience → feedback → learn

4 Paradigms — One Table

Paradigm Labels? Main Idea Memory Trick
Supervised ✅ Haan Correct answer dekar mapping learn SUPER = Teacher
Unsupervised ❌ Nahi Hidden structure discover UN = No Teacher
Semi-supervised Some ✅ + lots ❌ Limited labels + lots of raw data SEMI = Part-time Teacher
Reinforcement ❌ traditional labels nahi Actions + rewards/penalties RL = Game ka reward system

  • Example: Cat/Dog already defined
  • New image → Cat ✓

Clustering

  • Categories NOT given
  • Algorithm discovers groups
  • Example: Customers
  • → Group 1, 2, 3 discover hote hain
Classification = KNOWN labels predict karo
Clustering = UNKNOWN groups discover karo

Part 8 — 5 Confusions Abhi Clear Karo!

Confusion 1: "AI aur ML same hain?"

❌ Nahi! AI = Umbrella field. ML = major subset/approach within AI.

Confusion 2: "ML aur DL same hain?"

❌ Nahi! DL ⊂ ML. Deep Learning is a specialized ML approach based on deep neural networks.

Confusion 3: "Supervised = Classification?"

❌ Nahi! Classification supervised task hai, aur Regression bhi supervised task hai!

Supervised ├── Regression └── Classification
Confusion 4: "Unsupervised = Clustering?"

❌ Clustering is the major example, but unsupervised learning is broader. L0 mein clustering pe focus hai.

Confusion 5: "Labelled data = supervised learning automatically?"

Labels = key clue for supervised, but you still need to understand: what is the target? What task are you performing?

Lecture 10 — Feature Selection

"Jo features already available hain, unmein se kaunse rakhne chahiye?"

Feature Kya Hota Hai?

Stipend prediction problem:

Features (inputs):
  • CGPA ✅
  • IQ ✅
  • Number of Projects ✅
  • Attendance ✅
  • CGPA_copy ⚠️ (duplicate!)
  • Student_ID 🚫 (identifier!)
  • Random_number 🚫 (irrelevant!)

Target: Stipend

Kya ye saare 7 columns genuinely useful hain? NO!

Feature Selection vs Feature Transformation — VERY IMPORTANT!

Feature Transformation (L8)

  • Naya representation create karte ho
  • x → x² (new feature bana!)
  • Original se alag cheez bani

Feature Selection (L10)

  • Existing columns mein se choose karte ho
  • [x1, x2, x3, x4] → [x1, x3]
  • Koi naya feature create nahi!

3 Types of Feature Behaviour

✅
Relevant

Target prediction mein stable information provide karta hai. Example: Projects → Stipend

♻️
Redundant

Already-present feature ki information repeat karta hai. Example: CGPA_copy = CGPA

🗑️
Irrelevant

Stable predictive relationship nahi deta. Example: Random_number

"More Features = Better Model" — WRONG!

5 useful features + 20 random features → Training error kam ho sakti hai BUT validation performance worsen! Irrelevant features model ko random noise fit karne par force karte hain → variance increase → poor generalization.

Feature Selection ke Benefits

  • Generalization — Irrelevant features remove → unnecessary flexibility kam
  • Computation — Smaller matrix → less computation
  • Memory — Fewer columns → less storage
  • Interpretability — 7 features explain karna easy vs 700
  • Stability — Redundant features remove → multicollinearity reduce

    • Feature Selection — Part I: Filter Methods

    Filter Method = "Admission Gate" 🚪

    💡 Key Point

    Filter method typically does NOT repeatedly train the final predictive model for each feature subset. It uses simple statistical/structural checks — fast!

    Filter Method 1 — Duplicate Removal

    CGPACGPA_copy
    8.58.5
    9.09.0
    7.27.2
    Both columns same information! → One ko remove karo.
    ⚠️ Duplicate Rakhne se Kya Problem?

    Linear regression mein: Perfect Multicollinearity create ho sakti hai!

    X^T X singular ho sakta hai → (X^T X)^{-1} exist nahi karta!

    So duplicate removal = efficiency ke liye + mathematical stability ke liye!

    Kaun sa Rakhein?

    • Clearer/meaningful name
    • Fewer missing or corrupted values
    • Easier/cheaper to collect at prediction time
    • Ensure it's not a leakage column!

    Filter Method 2 — Variance Threshold

    Var(f_j) = (1/n) × Σ(x_ij − x̄_j)²

    Agar variance bahut low hai → feature observations ko distinguish karne mein kam useful ho sakta hai.

    Rule: Var(f_j) < τ (threshold) → remove candidate

    Constant feature: [5, 5, 5, 5, 5]
    Mean = 5, Deviation = 0 for all
    Var = 0 → obvious removal candidate!
    LOW Variance ≠ Useless! Suppose: [0, 0, 0, 0, 1] — Rare binary feature. Variance low. But maybe "1" = scholarship student, aur scholarship students ko ek specific stipend milta hai. That tiny feature can be HIGHLY predictive!
    HIGH Variance ≠ Predictive! Student_ID: 101, 102, 103... Values vary, variance non-zero. But does Student_ID predict stipend? NO! Variance only answers: "Feature varies kitna?" NOT: "Is it useful for predicting Y?"
    ✅ Variance Filter Actually Poochha Kya?

    "Does this feature have enough SPREAD to distinguish observations?"
    It does NOT ask: "Is it useful for predicting Y?"

    Filter Method 3 — Feature vs Target Correlation

    Better question for numeric variables: "Feature X_j aur target Y kitna linearly move karte hain?"

    r_jY = Σ(x_ij − x̄_j)(y_i − ȳ) / √[Σ(x_ij − x̄_j)² × Σ(y_i − ȳ)²]
    Range: -1 ≤ r ≤ +1
    r valueMatlab
    r ≈ +1Strong positive linear: x↑ → y↑
    r ≈ -1Strong negative linear: x↑ → y↓
    r ≈ 0Weak linear relationship

    🔥 MOST IMPORTANT WARNING: r = 0 ≠ No Predictive Value!

    Suppose: y = x²
    Take symmetric x: -2, -1, 0, 1, 2
    Then: y = 4, 1, 0, 1, 4

    Relationship PERFECTLY deterministic — given x, we know y exactly!
    Yet Pearson r = 0!

    Why? Pearson correlation measures LINEAR association only.
    Positive side pushes up, negative side also pushes up → cancel!
    y | | * * | * * | * +──────────────── x -2 -1 0 1 2 Perfect U-shape. r = 0 despite perfect nonlinear predictability!
    🔗 Lecture 8 Connection

    Lecture 8 mein humne x² use kiya curve capture karne ke liye.
    Lecture 10 mein: A Pearson-correlation filter could MISTAKENLY reject x if the true relationship is nonlinear!

    Input-Input Correlation

    X_i ↔ X_j check karte hain → redundant features aur multicollinearity find karne ke liye!

    Suppose: corr(X1, X2) = 0.95 → Both carry highly similar linear information → Maybe keep one!
    ⚠️ Correlated feature automatically delete mat karo!
    Example: x aur x² strongly correlated ho sakte hain, but BOTH may be necessary to represent a nonlinear pattern!

    Filter Methods — Summary

    FILTER | +----------+----------+ | | | Duplicate Variance Correlation removal threshold with target | + Input-input correlation Advantages: Fast, Simple, Scalable Limitations: Can miss interactions and nonlinear signal

    Feature Selection — Part II: Wrapper Methods

    Why Filters Aren't Enough?

    💡 The Interaction Problem

    Suppose X1 alone weak hai. X2 alone bhi weak hai. But together (X1, X2) extremely powerful!

    Y = X1 × X2

    Ek-ek feature dekhne wala filter miss kar dega. Wrapper method kehta hai: "Let's actually TRAIN the model on subsets!"

    Wrapper Method = Model in the Loop 🔄

    Choose subset → Train model → Validate → Choose next subset → ... Isko "wrapper" bolte hain kyunki predictive model is effectively WRAPPED INSIDE the feature-selection process.

    Validation Use Karna Kyun Zaroori?

    Random feature add karo → Training error: 5 → 2 (looks amazing!)
    But Validation error: 8 → 10 (worse!)

    Feature ne generalization help nahi ki!

    Hence wrapper selection MUST use validation/cross-validated performance, NOT training performance!

    Exhaustive Feature Selection

    p features ke liye, har feature Include ya Exclude:

    Total nonempty subsets = 2^p - 1
    p = 3 → 2³ - 1 = 7 subsets
    {A}, {B}, {C}, {A,B}, {A,C}, {B,C}, {A,B,C}

    p = 20 → 2²⁰ - 1 = 1,048,575 (over 1 million!)
    p = 30 → 2³⁰ - 1 = 1,073,741,823 (over 1 BILLION!)

    Computational cost: EXPONENTIAL 💀
    Exhaustive ka Doosra Problem: 1,000,000 subsets test karo → One may look best on validation simply due to RANDOM LUCK → Search itself can overfit the validation procedure!

    Backward Elimination

    📉 Strategy: Start with ALL features, remove one by one

    Every step mein: locally best next move choose karo.

    🚨 Backward Greedy kyun hai?
    Once f3 removed → gone forever! Maybe future mein {f3, f4} combination useful hota. But since f3 was already deleted, algorithm never explores it. → Greedy search can MISS global optimum!

    Backward Elimination Computational Cost

    Path length ≈ 1 + p + (p-1) + ... + 2 = p(p+1)/2
    Cost: O(p²) vs Exhaustive O(2^p)
    p = 6:
    Exhaustive: 2⁶ - 1 = 63 subsets
    Backward path: 6×7/2 = 21 subsets

    Much less than exhaustive!

    Feature Selection — Part III: Leakage 🚨

    Sabse Important Topic of Lecture 10

    Suppose entire dataset ka use karke correlation calculate kiya, top 5 features select kiye, PHIR train/validation split kiya. PROBLEM: Validation data already feature selection mein influence kar chuka hai. Model ne validation set ko indirectly PEEK kar liya. Yeh hai: DATA LEAKAGE!

    Wrong Pipeline ❌

    Entire Dataset ↓ Compute correlation ↓ Select top 5 features ↓ Split into Train / Validation ↓ Cross-validation ❌ WRONG! Feature-selection decision already saw all data. Validation is no longer truly untouched.

    Correct Pipeline ✅

    Raw data ↓ Split / CV fold ↓ Training portion ONLY ↓ Fit feature selector (using training data only!) ↓ Select features ↓ Train model on selected features ↓ Apply SAME selection to untouched validation portion ↓ Evaluate Then next CV fold repeats with its own training subset!
    ⚠️ Why This Matters?

    Suppose correlation threshold iteself is learned from all data. Then validation set influenced WHICH features survived. So validation isn't truly independent anymore.

    Result: CV score = 0.90 report karte ho, but actual unseen performance = 0.75!

    Leakage ⟹ Optimistic Evaluation ⚠️

    Final Test Set ka GOLDEN RULE 🏆

    Test set ko KABHI feature selection mein use mat karo!
    Not for choosing correlation threshold
    Not for choosing number of features
    Not for comparing candidate subsets
    → Final test evaluation: ONCE, at the very end!

    End-to-End Feature Selection Workflow

    1. Goal & Metrics define karo
    2. Data split karo (Train / Validation / Test)
    3. Duplicates aur structurally unusable columns remove karo
    4. Filter methods apply karo (training data pe)
    5. Wrapper search karo (CV ke andar)
    6. Thresholds/counts/stopping rules choose karo inside CV
    7. All-feature baseline se compare karo
    8. Final untouched test evaluation — ONCE!

    Selected Features = NOT Universal Truth!

    💡 Feature Usefulness is Conditional

    Suppose experiment selected: {CGPA, Projects, Attendance}

    Change the target Y1 → Y2 → Useful features change

    Change the model: Linear Regression vs Decision Tree → features change

    Change the metric: RMSE vs MAE → preferred subset change

    Change the sample → different features!

    Useful(feature) = f(target, model, metric, sample, validation design)

    Smallest Feature Set = NOT Always Best!

    Model A: 7 features, CV score = 0.84
    Model B: 18 features, CV score = 0.841

    Almost identical performance → prefer simpler 7-feature model

    But larger model retain karo agar:
    → Domain knowledge justify karta hai
    → Measurement reliability
    → Meaningful validated advantage

    "Fewest possible features" is NOT an absolute objective!

    🚨 Feature Selection Traps — All in One!

    Trap 1: "Student_ID has high variance → must be predictive"

    ❌ WRONG! Variance = spread, NOT relevance!

    Trap 2: "Scholarship_flag only 3% students → remove it"

    ❌ WRONG! Rare ≠ Useless!

    Trap 3: "Project_depth and Project_depth² correlated → delete x²"

    ❌ WRONG! x² wahan curvature model karne ke liye tha! High correlation ≠ automatically redundant!

    Trap 4: "Pearson r = 0 → feature cannot predict"

    ❌ WRONG! y = x² perfectly predictable but r = 0!

    Trap 5: "Feature selection before CV" — Validation Leakage!

    ❌ WRONG! Feature selection MUST happen inside CV, using only training fold data!

    Feature Selection vs PCA — THE CORE DIFFERENCE

    Feature Selection (L10)

    Original axes: x1, x2, x3, x4

    PCA → New axes BANATA hai 🔄

    PCA Kya Hai?

    📚 Definition

    PCA is an unsupervised linear feature-extraction method that finds a new set of orthogonal axes along which the variance of the data is maximized.

    Human language mein: Data ko aise rotate karo ki pehla new direction data ka maximum spread capture kare, phir second direction remaining largest spread, aur so on. Phir low-importance directions hata do.

    "Maximum Variance" Kyun?

    Data aise dikhta hai (diagonal direction mein spread):
    x2 | * | * | * | * +────────────── x1 Original x1 axis mein kuch info, x2 mein bhi, but actual important direction = diagonal ↗ PCA woh diagonal direction (PC1) pick karega!
    ⚠️ PCA is Unsupervised!

    Standard PCA does NOT use target Y to find directions. It only looks at X and its variance/covariance structure.

    BIG LIMITATION: Suppose target depends on a low-variance direction. PCA may remove it! High variance ≠ high predictive relevance!

    PCA Mathematics — Step by Step

    Notation Table

    SymbolMatlab
    nNumber of observations (rows)
    pOriginal features (columns)
    kRetained principal components
    XOriginal n×p data matrix
    μVector of feature means
    X_cCentered data
    SCovariance matrix (p×p)
    v_jEigenvector / PC direction
    λ_jEigenvalue / variance captured
    W_kMatrix of first k eigenvectors (p×k)
    ZTransformed PC scores (n×k)

    Step 1 — Mean Centering

    x_c = x - x̄ (for one feature)
    X_c = X - 1·μᵀ (for matrix form)

    Result: Every feature has mean = 0

    💡 Kyun Center Karte Hain?

    PCA is about spread AROUND THE CENTER, not distance from some arbitrary origin. Centering ke baad coordinates represent karte hain: "average se kitna door?"

    Standardization — Kabhi Zaroori Hai?

    Sirf Centering

    • Jab features comparable units/scales mein hon
    • Just x - μ

    Standardization

    • Jab units alag hain
    • Income: 500,000 vs Age: 20
    • z = (x - μ) / s
    • Income ki scale dominate na kare!
    Split FIRST! Phir training data ke means/scales calculate karo. Validation/test data par SAME transformation apply karo. Never standardize on full dataset then CV!

    Covariance — Intuition Samjho

    💡 Variance vs Covariance

    Variance: "Ek feature khud kitna spread karta hai?"

    Covariance: "Do features saath mein kaise move karte hain?"

    Cov(x, y) = (1/(n-1)) × Σ(x_i - x̄)(y_i - ȳ)
    SignMatlab
    Cov > 0Both tend to be above/below average together (same direction)
    Cov < 0One high when other low (opposite direction)
    Cov ≈ 0Little linear co-movement
    Cov = 0 ≠ Independence! y = x² example: perfectly deterministic, but covariance = 0! Same as Pearson r = 0 trap!

    Covariance Matrix (p×p)

    S = (1/(n-1)) × X_cᵀ X_c For 3 features: [Var(X1) Cov(X1,X2) Cov(X1,X3)] S = [Cov(X2,X1) Var(X2) Cov(X2,X3)] [Cov(X3,X1) Cov(X3,X2) Var(X3) ]
    ✅ Key Properties

    Diagonal entries: Variances of individual features

    Off-diagonal entries: Pairwise covariances

    S = Sᵀ → Symmetric (Cov(Xi, Xj) = Cov(Xj, Xi))

    Eigenvectors — The Magic Word!

    🔮 Eigen Equation
    Sv = λv

    v = eigenvector (direction)
    λ = eigenvalue (how much this direction captures)

    Normally matrix A rotates a vector. For eigenvector: direction stays same, only size changes!

    General vector: Eigenvector: ↗ → ↗ A changes direction A only stretches/shrinks! Same line, different length!

    PCA mein Eigenvectors ka Role

    ⭐ Central Mathematical Result

    Eigenvectors of covariance matrix = Principal Directions

    Eigenvalues = Variance captured in those directions

    This is the ELEGANT SOLUTION to the maximum-variance problem!

    Eigenvalue Equation

    |S - λI| = 0 → find eigenvalues λ Then: Sv = λv → find eigenvectors v

    Principal Components ka Ranking

    Suppose eigenvalues:
    λ1 = 10 → PC1 captures variance 10 (MOST)
    λ2 = 3 → PC2 captures variance 3
    λ3 = 1 → PC3 captures variance 1

    PC1 = eigenvector associated with LARGEST eigenvalue!
    Sort eigenvalues: λ1 ≥ λ2 ≥ λ3 ≥ ...

    Orthogonal Means What?

    PC1 aur PC2 perpendicular hote hain (90°):
    PC1 → ↑ │ PC2 │
    PC1 and PC2 are perpendicular directions. Transformed covariance becomes DIAGONAL (no cross-terms)!

    Projection — "Point ko New Axis Par Measure Karna"

    z = uᵀx (projection score)

    Where u = unit direction, x = centered data point, z = scalar coordinate along that direction.

    x = [3, 1]ᵀ
    u = (1/√2)[1, 1]ᵀ

    z = uᵀx = (1/√2)(3) + (1/√2)(1) = 4/√2 = 2√2 ≈ 2.828

    Projected point: zu = [2, 2]ᵀ (point on the direction line)

    Original: [3, 1], Projected: [2, 2] → Different!

    Residual (info lost): e = x - zu = [1, -1]ᵀ

    Pythagorean Decomposition

    ||x||² = z² + ||e||²

    "Original energy = captured part + lost part"

    PCA preserves maximum z² (captured part) when reducing dimensions!

    PCA Core Optimization

    max over ||u||=1: Var(uᵀX)

    Which u produces maximum variance of projected scores?

    Answer: u = eigenvector of covariance matrix!

    PCA Numerical Example — Step by Step 🔢

    Three Houses Dataset

    HouseBedroom (f1)Washroom (f2)
    A21
    B43
    C65

    Step 1 — Calculate Mean

    Bedroom mean: x̄1 = (2+4+6)/3 = 4
    Washroom mean: x̄2 = (1+3+5)/3 = 3

    μ = [4, 3]ᵀ

    Step 2 — Center the Data

    House A: (2-4, 1-3) = (-2, -2)
    House B: (4-4, 3-3) = (0, 0)
    House C: (6-4, 5-3) = (2, 2)

    Xc = [[-2, -2], [0, 0], [2, 2]]

    Step 3 — Covariance Matrix

    S = (1/(n-1)) × Xcᵀ Xc = (1/2) × Xcᵀ Xc
    S = [[4, 4], [4, 4]]

    Step 4 — Eigenvalues & Eigenvectors

    PC1 (Most Variance)

    v1 = (1/√2)[1, 1]ᵀ

    λ1 = 8

    Direction: both features increase together → "overall house size"

    PC2 (Least Variance)

    v2 = (1/√2)[1, -1]ᵀ

    λ2 = 0

    Direction: bedroom vs washroom contrast. But ZERO variance!

    Step 5 — Project Onto PC1

    Z1 = Xc × v1
    House A: (-2, -2) · (1/√2, 1/√2) = -2√2 ≈ -2.83
    House B: (0, 0) · (1/√2, 1/√2) = 0
    House C: (2, 2) · (1/√2, 1/√2) = 2√2 ≈ 2.83

    Z1 = [-2.83, 0, 2.83]ᵀ

    Step 6 — Explained Variance Ratio

    Total variance = λ1 + λ2 = 8 + 0 = 8
    EVR1 = 8 / (8+0) = 1 = 100%!
    ✅ Lossless Compression!

    PC1 alone preserves ALL variance. Why?

    All three houses lie on a straight line: f2 = f1 - 1

    There's only ONE degree of freedom. PCA discovers that hidden 1D structure!

    λ2 = 0 Kyun?

    Data points: (2,1), (4,3), (6,5) — all on y = x-1 line
    No variation perpendicular to this line!
    PC2 direction (1,-1) is perpendicular to data's actual spread
    → Zero spread in that direction → λ2 = 0
    🧠 Eigenvalue Geometric Meaning
    λ_j = VARIANCE of the data scores along v_j

Large λ → big spread → important direction ⭐
Small λ → tiny spread → less variance
λ = 0   → NO spread in that direction

    PCA Pipeline & Choosing k

    Complete PCA Pipeline

    1. Data split karo (Train / Validation / Test) — PEHLE!
    2. Training data pe mean (μ_train) aur scale (s_train) calculate karo
    3. Training data center/scale karo
    4. S = (1/(n-1)) × Xcᵀ Xc → Covariance matrix
    5. Eigendecomposition: Sv_j = λ_j v_j for all j
    6. Eigenvalues sort karo: λ1 ≥ λ2 ≥ ... ≥ λp
    7. k choose karo (number of components to keep)
    8. W_k = [v1, v2, ..., vk] matrix banao (p×k)
    9. Transform: Z_train = X_c,train × W_k (n×k result)
    10. Test data: Z_test = (X_test - 1·μ_train) × W_k

    Test Data Transform — Very Important!

    Z_test = (X_test - 1·μ_train^T) × W_k
    Use μ_train, NOT test mean! Same fitted PCA directions W_k use karo. KABHI test pe PCA refit mat karo. Agar test ka apna mean use karo → Information leakage!

    Total Variance aur EVR

    Total variance = Σλ_j = trace(S)
    EVR_j = λ_j / Σλ_ℓ (explained variance ratio)
    Cumulative EVR_k = Σ(j=1 to k) λ_j / Σλ_ℓ

    Example: Choosing k

    Suppose eigenvalues: λ = [6, 2, 1, 0.5], Total = 9.5

    kCumulative Variance≥ 90%?
    k=16/9.5 = 63.2%❌
    k=28/9.5 = 84.2%❌
    k=39/9.5 = 94.7%✅

    Smallest k reaching 90%: k = 3

    k = 3 automatically BEST hai? NO! PCA maximizes VARIANCE, not prediction accuracy! Maybe PC4 carries only 5.3% variance but is CRITICAL for the target. → k should be VALIDATED against actual downstream task!

    Ways to Choose k

    📊
    Variance Threshold

    Smallest k reaching 90%/95%. But then validate!

    📈
    Scree Plot

    Find where eigenvalues stop dropping rapidly (elbow)

    👁️
    Visualization

    k=2 or k=3 for human inspection

    🔧
    Downstream CV

    Treat k as hyperparameter inside cross-validation

    Scree Plot

    λ (eigenvalue) | | ██████████████ | ██████████ | ████ | ██ | █ | ▌ +────────────────────> PC number 1 2 3 4 5 6 Elbow ≈ where curve bends (diminishing returns after this point) Maybe k = 2 or 3 here.

    PCA Leakage — BAHUT IMPORTANT!

    WRONG: Entire dataset → Standardize → PCA → 5 PCs → 5-fold CV

    WHY WRONG? Means, scales, eigenvectors use ALL observations including validation folds. So validation folds influenced the transformation. Performance reported = Optimistic/Inflated!

    Correct PCA + CV Pipeline

    For EACH fold: Training fold ↓ Compute μ_train, scale_train ↓ Center/scale training data ↓ Compute covariance ↓ Find eigenvectors ↓ Fix k ↓ Transform training data ↓ Transform validation using SAME training μ/scale/eigenvectors ↓ Train downstream model ↓ Evaluate validation Then next fold repeats the ENTIRE process!

    Bias-Variance Connection to PCA

    k ↓ (fewer components)

    • Representation complexity ↓
    • Variance may ↓ (good!)
    • Approximation bias ↑ (bad!)
    • Simpler model

    k ↑ (more components)

    • Representation complexity ↑
    • Variance may ↑
    • Approximation bias ↓
    • More faithful to data

    PCA dimensionality reduction itself participates in the bias-variance tradeoff!

    When PCA Fails 🚫

    Failure Case 1 — Circular Data

    *** * * * + * (circle of points) * * ***
    All directions have roughly equal spread → λ1 ≈ λ2
    No obvious dominant direction!
    PCA has no unique "best" direction carrying most variance.

    Failure Case 2 — Class Information in Low-Variance Direction

    A A A A A A ──────────────── PC1 (main variance direction) B B B B B B
    Classes differ in vertical direction.
    PCA doesn't know about labels (unsupervised!).
    It picks PC1 = horizontal (most total variance).
    Projecting onto PC1 → Classes A and B MERGE! 😱
    Class information DESTROYED!

    Failure Case 3 — Nonlinear Data

    Suppose data lies on a curve like y = x²
    PCA is LINEAR — it can rotate/project but can't "unroll" a curved manifold!
    Linear projection can squash important nonlinear structure.
    PCA Helps When...PCA Does NOT Guarantee...
    Visualization (k=2 or 3)Better prediction
    CompressionClass separation
    Faster downstream learningCausal meaning preserved
    Remove linear redundancyTarget-relevant info preserved
    Noise reduction (if low-var ≈ noise)Nonlinear structures captured

    PCA aur Multicollinearity

    X1 ≈ X2 (highly correlated features)

    PCA creates:
    PC1 ≈ X1 + X2 (large variance direction)
    PC2 ≈ X1 - X2 (tiny variance → maybe remove)

    Dimensionality reduces aur linear redundancy bhi reduce hoti hai!
    Linear model coefficients potentially more stable.
